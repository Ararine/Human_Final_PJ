# 구독 상태별 변경 테이블 정리

이 문서는 구독 관련 주요 사용자 액션에서 실제로 변경되는 테이블을 정리한다.

기준 코드:

- `backend/models/user.py`: OAuth 가입 및 무료 구독 생성
- `backend/services/payment.py`: 첫 유료 구독 결제 확정, 업그레이드 결제 확정
- `backend/services/billing.py`: 빌링키 저장
- `backend/services/subscription.py`: 구독 생성/연장, 업그레이드, 다운그레이드/취소 예약
- `backend/services/subscription_renewal.py`: 예약 다운그레이드 및 구독 갱신 처리

## 1. 첫 구독

첫 구독은 현재 코드상 두 흐름으로 나뉜다.

### 1.1 첫 로그인 시 무료 구독 생성

OAuth로 신규 사용자가 생성될 때 무료 플랜 구독이 함께 생성된다.

| 테이블 | 작업 | 변경 내용 |
| --- | --- | --- |
| `users` | INSERT | 신규 사용자 계정 생성 |
| `subscriptions` | INSERT | `free` 플랜 기준 활성 구독 생성 |
| `oauth_accounts` | INSERT | OAuth 제공자 계정 연결 정보 저장 |
| `user_credit_balances` | INSERT | 신규 가입 기본 크레딧 잔액 생성 |
| `credit_ledger` | INSERT | 신규 가입 크레딧 지급 원장 기록 |

주요 변경 필드:

- `subscriptions`: `user_id`, `plan_id`, `status = 'active'`, `started_at`, `renew_at`, `created_at`, `updated_at`
- `user_credit_balances`: `user_id`, `balance`, `updated_at`
- `credit_ledger`: `user_id`, `amount`, `balance_after`, `entry_type = 'first_login'`, `source_type = 'oauth'`

### 1.2 첫 유료 구독 결제 성공

무료 플랜 사용자가 유료 플랜을 처음 결제하면 결제 내역, 빌링키, 구독 정보가 생성 또는 갱신된다.

| 테이블 | 작업 | 변경 내용 |
| --- | --- | --- |
| `payments` | INSERT | 정기 구독 결제 내역을 `ready` 상태로 생성 |
| `payments` | UPDATE | Toss 결제 승인 성공 후 `success` 상태 및 PG 승인 정보 갱신 |
| `billing_keys` | INSERT | Toss 빌링키를 암호화하여 저장 |
| `subscriptions` | INSERT 또는 UPDATE | 유료 플랜 구독 생성, 기존 동일 플랜 구독이 있으면 기간 연장/재활성화 |
| `payments` | UPDATE | 생성된 `subscription_id`를 결제 내역에 연결 |
| `user_credit_balances` | INSERT 또는 UPDATE | 플랜 기본 크레딧이 있으면 잔액 지급 |
| `credit_ledger` | INSERT | 플랜 기본 크레딧 지급 원장 기록 |

주요 변경 필드:

- `payments`: `product_type = 'subscription'`, `plan_id`, `amount`, `status`, `pg_provider`, `pg_transaction_id`, `payment_method`, `toss_status`, `approved_at`, `paid_at`, `subscription_id`
- `billing_keys`: `user_id`, `pg_provider`, `encrypted_billing_key`, `billing_key_hash`, `customer_key`, `card_company`, `masked_card_number`, `method_type`, `status = 'active'`
- `subscriptions`: `plan_id`, `status = 'active'`, `started_at`, `ended_at`, `renew_at`, `current_period_start`, `current_period_end`, `next_billing_at`, `auto_renew = true`, `cancel_at_period_end = false`, `billing_status = 'paid'`, `last_payment_id`, `billing_key_id`
- `user_credit_balances`: 플랜 기본 크레딧만큼 `balance` 증가
- `credit_ledger`: `entry_type = 'grant'`, `source_type = 'subscription'`, `source_id = subscription_id`

참고:

- 기존 동일 플랜 구독이 아직 활성 상태이면 `subscriptions`는 새 행 생성이 아니라 기존 행의 기간을 연장한다.
- 기존 동일 플랜 구독이 만료/취소 상태이면 같은 행을 다시 `active`로 재활성화한다.

## 2. 업그레이드

낮은 등급의 유료 플랜에서 높은 등급의 유료 플랜으로 변경할 때는 즉시 적용된다.

| 테이블 | 작업 | 변경 내용 |
| --- | --- | --- |
| `payments` | INSERT | 업그레이드 정산 결제 내역을 `ready` 상태로 생성 |
| `payments` | UPDATE | 결제 성공 후 `success` 상태 및 PG 승인 정보 갱신 |
| `billing_keys` | INSERT | 새 빌링키 저장 |
| `subscriptions` | INSERT | 상위 플랜의 새 활성 구독 생성 |
| `subscriptions` | UPDATE | 기존 하위 플랜 구독을 즉시 `cancelled` 처리 |
| `subscription_plan_changes` | UPDATE | 기존 구독에 연결된 예약 변경이 있으면 `cancelled` 처리 |
| `subscription_plan_changes` | INSERT | 업그레이드 정산 이력 생성 |
| `payments` | UPDATE | 새 상위 플랜 `subscription_id`를 결제 내역에 연결 |
| `user_credit_balances` | INSERT 또는 UPDATE | 상위 플랜 기본 크레딧이 있으면 잔액 지급 |
| `credit_ledger` | INSERT | 상위 플랜 기본 크레딧 지급 원장 기록 |

주요 변경 필드:

- 신규 상위 `subscriptions`: `plan_id`, `status = 'active'`, `current_period_start`, `current_period_end`, `next_billing_at`, `auto_renew = true`, `cancel_at_period_end = false`, `billing_status = 'paid'`, `last_payment_id`, `billing_key_id`
- 기존 하위 `subscriptions`: `status = 'cancelled'`, `ended_at = NOW()`, `renew_at = NULL`, `current_period_end = NOW()`, `next_billing_at = NULL`, `auto_renew = false`, `billing_status = 'cancelled'`, `cancelled_at`
- `subscription_plan_changes`: `change_type = 'upgrade'`, `apply_timing = 'immediate'`, `status = 'applied'`, `from_plan_id`, `to_plan_id`, `from_subscription_id`, `to_subscription_id`, `remaining_amount`, `discount_amount`, `charged_amount`, `applied_at`

참고:

- 업그레이드 금액은 남은 기간 가치를 차감한 정산 금액으로 계산된다.
- 정산 금액이 0원이면 Toss 결제 요청을 우회하고 내부 성공 처리로 진행한다.

## 3. 다운그레이드

높은 등급의 유료 플랜에서 낮은 등급의 플랜으로 변경할 때는 즉시 적용하지 않고 현재 이용 기간 종료 시점으로 예약된다.

### 3.1 다운그레이드 예약 시점

| 테이블 | 작업 | 변경 내용 |
| --- | --- | --- |
| `subscription_plan_changes` | UPDATE | 같은 기존 구독에 걸린 기존 `scheduled` 다운그레이드 예약을 `cancelled` 처리 |
| `subscription_plan_changes` | INSERT | 새 다운그레이드 예약 생성 |

주요 변경 필드:

- `subscription_plan_changes`: `change_type = 'downgrade'`, `apply_timing = 'period_end'`, `status = 'scheduled'`, `from_plan_id`, `to_plan_id`, `from_subscription_id`, `effective_at = current_period_end`

참고:

- 예약 시점에는 현재 `subscriptions` 행을 바로 낮은 플랜으로 바꾸지 않는다.
- 기존 구독은 현재 기간 종료일까지 유지된다.

### 3.2 다운그레이드 적용 시점

스케줄러가 `effective_at`이 지난 예약 다운그레이드를 처리한다.

| 테이블 | 작업 | 변경 내용 |
| --- | --- | --- |
| `subscription_billing_attempts` | INSERT | 다운그레이드 적용 결제 시도 기록 |
| `payments` | INSERT | 새 낮은 플랜의 결제 성공 내역 생성 |
| `subscriptions` | UPDATE | 기존 상위 플랜 구독을 `cancelled` 처리 |
| `subscriptions` | INSERT | 낮은 플랜의 새 활성 구독 생성 |
| `subscriptions` | UPDATE | 새 구독에 `last_payment_id` 연결 |
| `subscription_plan_changes` | UPDATE | 예약 변경을 `applied` 처리하고 `to_subscription_id` 연결 |
| `billing_keys` | UPDATE | 사용된 빌링키의 `last_used_at` 갱신 |

주요 변경 필드:

- 기존 상위 `subscriptions`: `status = 'cancelled'`, `ended_at = NOW()`, `current_period_end = NOW()`, `billing_status = 'cancelled'`
- 신규 낮은 플랜 `subscriptions`: `plan_id = to_plan_id`, `status = 'active'`, `current_period_start`, `current_period_end`, `next_billing_at`, `auto_renew = true`, `cancel_at_period_end = false`, `billing_status = 'paid'`, `billing_key_id`
- `subscription_plan_changes`: `status = 'applied'`, `applied_at`, `to_subscription_id`
- `subscription_billing_attempts`: `attempt_type = 'scheduled_downgrade'`, `status = 'success'` 또는 `failed`

참고:

- 빌링키가 없거나 결제가 실패하면 `subscription_plan_changes.status`가 `failed`로 바뀌고 새 구독은 생성되지 않는다.

## 4. 구독 취소

구독 취소는 현재 유료 구독을 즉시 끊는 방식이 아니라, 현재 이용 기간 종료 후 무료 플랜으로 전환되도록 예약하는 방식이다.

### 4.1 취소 예약 시점

| 테이블 | 작업 | 변경 내용 |
| --- | --- | --- |
| `subscriptions` | UPDATE | 현재 구독에 기간 종료 취소 플래그 설정 |
| `subscription_plan_changes` | UPDATE | 기존 예약 다운그레이드/무료 전환 예약을 `cancelled` 처리 |
| `subscription_plan_changes` | INSERT | 무료 플랜 전환 예약 생성 |

주요 변경 필드:

- `subscriptions`: `auto_renew = false`, `cancel_at_period_end = true`, `cancelled_at = NOW()`, `status = 'active'`
- `subscription_plan_changes`: `change_type = 'cancel_to_free'`, `apply_timing = 'period_end'`, `status = 'scheduled'`, `from_plan_id`, `to_plan_id = free plan`, `from_subscription_id`, `effective_at = current_period_end`

참고:

- 취소 예약 후에도 현재 이용 기간 동안 기존 유료 구독은 `active` 상태로 유지된다.

### 4.2 취소 적용 시점

무료 플랜 전환 예약도 스케줄러의 예약 다운그레이드 처리 흐름을 탄다.

| 테이블 | 작업 | 변경 내용 |
| --- | --- | --- |
| `subscription_billing_attempts` | INSERT | 무료 플랜 전환 처리 시도 기록 |
| `payments` | INSERT | 무료 플랜 전환 결제 기록 생성, 금액은 보통 0원 |
| `subscriptions` | UPDATE | 기존 유료 구독을 `cancelled` 처리 |
| `subscriptions` | INSERT | 무료 플랜의 새 활성 구독 생성 |
| `subscriptions` | UPDATE | 새 무료 구독에 `last_payment_id` 연결 |
| `subscription_plan_changes` | UPDATE | 무료 전환 예약을 `applied` 처리하고 `to_subscription_id` 연결 |
| `billing_keys` | UPDATE | 사용된 빌링키의 `last_used_at` 갱신 |

주요 변경 필드:

- 기존 유료 `subscriptions`: `status = 'cancelled'`, `ended_at = NOW()`, `current_period_end = NOW()`, `billing_status = 'cancelled'`
- 신규 무료 `subscriptions`: `plan_id = free plan`, `status = 'active'`, `current_period_start`, `current_period_end`, `next_billing_at`, `auto_renew = true`, `cancel_at_period_end = false`, `billing_status = 'paid'`
- `subscription_plan_changes`: `status = 'applied'`, `applied_at`, `to_subscription_id`
- `payments`: `product_type = 'subscription'`, `amount = 0`, `status = 'success'`, `payment_method = 'free_bypass'`

참고:

- 현재 구현의 예약 적용 함수는 다운그레이드와 무료 전환을 같은 흐름으로 처리한다.
- 무료 플랜 금액이 0원이면 PG 결제 요청 없이 내부 성공 처리된다.

## 5. 요약 표

| 액션 | 즉시 변경 테이블 | 예약/스케줄러 적용 시 추가 변경 테이블 |
| --- | --- | --- |
| 첫 로그인 무료 구독 | `users`, `subscriptions`, `oauth_accounts`, `user_credit_balances`, `credit_ledger` | 없음 |
| 첫 유료 구독 | `payments`, `billing_keys`, `subscriptions`, `user_credit_balances`, `credit_ledger` | 없음 |
| 업그레이드 | `payments`, `billing_keys`, `subscriptions`, `subscription_plan_changes`, `user_credit_balances`, `credit_ledger` | 없음 |
| 다운그레이드 예약 | `subscription_plan_changes` | `subscription_billing_attempts`, `payments`, `subscriptions`, `subscription_plan_changes`, `billing_keys` |
| 구독 취소 예약 | `subscriptions`, `subscription_plan_changes` | `subscription_billing_attempts`, `payments`, `subscriptions`, `subscription_plan_changes`, `billing_keys` |

## 6. 추가 고려사항

### 필수

- 없음.

### 권장

- 기존 `docs/subscriptions/subscription_table_changes.md`는 현재 인코딩이 깨져 보이므로, 필요하면 이 문서를 기준으로 교체하거나 인코딩 복구 여부를 확인한다.

### 후순위

- 정기 갱신 성공/실패 시 변경 테이블도 별도 문서로 분리하면 운영 확인용으로 유용하다.
