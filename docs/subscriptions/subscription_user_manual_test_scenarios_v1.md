# GARIM 구독 기능 사용자용 수동 테스트 시나리오 v1

> 기준 문서: `docs/subscriptions/subscription_30day_auto_renewal_final_v2_with_model_guide.md`  
> 목적: Codex/자동화 테스트가 아니라, 사람이 직접 화면을 보면서 구독 기능이 정상 동작하는지 확인하기 위한 사용자용 테스트 체크리스트입니다.

## 0. 테스트 전 꼭 확인할 것

### 0.1 테스트 계정 준비

아래 계정을 분리해서 테스트하는 것을 권장합니다.

| 계정 | 시작 상태 | 용도 |
|---|---|---|
| TEST_FREE | Free | 신규 유료 구독 테스트 |
| TEST_PRO | Pro | 업그레이드/취소 테스트 |
| TEST_STUDIO | Studio | 다운그레이드/Free 변경 테스트 |

계정이 하나뿐이라면, 테스트 후 DB 초기화 또는 관리자 기능으로 구독 상태를 초기화해야 합니다.

---

### 0.2 테스트 결제 환경

- 실제 운영 결제가 아니라 Toss Payments 샌드박스 또는 테스트 결제 환경에서 진행합니다.
- 결제 성공/실패 테스트가 가능해야 합니다.
- 테스트 중 실제 카드 결제가 발생하지 않는지 먼저 확인합니다.
- 결제 완료 후 영수증 또는 결제 완료 화면이 표시되는지 확인합니다.

---

### 0.3 화면에서 공통으로 확인할 항목

구독 관련 테스트에서는 매번 아래 항목을 확인합니다.

| 확인 항목 | 정상 기준 |
|---|---|
| 현재 플랜 | Free / Pro / Studio 중 현재 적용 플랜이 정확히 표시 |
| 다음 결제일 | 유료 플랜이면 다음 자동결제 예정일 표시 |
| 사용 가능 기간 | 취소/변경 예약 상태에서도 종료일까지 권한 유지 |
| 변경 예약 안내 | 다운그레이드 또는 Free 변경 시 예약 문구 표시 |
| 결제 상태 | 결제 성공/실패 결과가 사용자에게 명확히 표시 |
| 버튼 상태 | 현재 불가능한 작업은 버튼 비활성화 또는 안내 표시 |

# 2. 기본 구독 테스트

## TC-USER-001. Free 사용자가 Pro로 구독한다

### 목적

Free 사용자가 Pro 플랜을 결제하면 즉시 Pro 권한이 적용되는지 확인합니다.

### 사전 조건

- 로그인한 사용자의 현재 플랜이 Free입니다.
- 결제 가능한 테스트 결제 수단이 준비되어 있습니다.

### 테스트 절차

1. 로그인합니다.
2. 구독/요금제 페이지로 이동합니다.
3. 현재 플랜이 `Free`로 표시되는지 확인합니다.
4. `Pro 구독하기` 또는 Pro 선택 버튼을 클릭합니다.
5. 결제 화면으로 이동하는지 확인합니다.
6. 테스트 결제를 성공 처리합니다.
7. 결제 완료 후 서비스 화면으로 돌아옵니다.
8. 마이페이지 또는 구독 관리 페이지에서 현재 플랜을 확인합니다.

### 기대 결과

- 결제 성공 메시지가 표시됩니다.
- 현재 플랜이 `Pro`로 변경됩니다.
- Pro 권한이 즉시 사용 가능합니다.
- 다음 결제 예정일이 결제일 기준 약 30일 뒤로 표시됩니다.
- Free 플랜으로 표시되거나 권한이 막히면 실패입니다.

# 3. 업그레이드 테스트

## TC-USER-003. Pro 사용자가 Studio로 업그레이드한다

### 목적

Pro 사용자가 Studio로 변경하면 즉시 결제되고 Studio가 바로 적용되는지 확인합니다.

### 사전 조건

- 현재 플랜이 Pro입니다.
- Pro의 남은 기간이 존재합니다.

### 테스트 절차

1. Pro 계정으로 로그인합니다.
2. 구독 관리 페이지에서 현재 플랜이 `Pro`인지 확인합니다.
3. `Studio로 업그레이드` 버튼을 클릭합니다.
4. 결제 안내 화면에서 Studio 결제 금액이 표시되는지 확인합니다.
5. 테스트 결제를 성공 처리합니다.
6. 결제 완료 후 구독 관리 페이지로 돌아옵니다.
7. 현재 플랜이 Studio로 바뀌었는지 확인합니다.
8. Pro 잔여 기간 이월 안내가 화면에 표시되는지 확인합니다.

### 기대 결과

- Studio 결제가 즉시 진행됩니다.
- 현재 플랜이 `Studio`로 즉시 변경됩니다.
- Studio 종료 이후 Pro 잔여 기간이 남아 있다는 안내가 표시됩니다.
- 기존 Pro가 즉시 사라지거나 잔여 기간 안내가 없으면 확인 필요입니다.
- Pro와 Studio가 동시에 자동결제될 것처럼 표시되면 실패입니다.

### 결과

- [ ] 성공
- [ ] 실패
- [ ] 보류

## TC-USER-004. 업그레이드 후 하위 플랜 중복 자동결제가 없어야 한다

### 목적

Pro에서 Studio로 업그레이드한 뒤 Pro와 Studio가 동시에 자동결제 대상으로 표시되지 않는지 확인합니다.

### 사전 조건

- TC-USER-003을 완료했습니다.
- 현재 플랜이 Studio입니다.

### 테스트 절차

1. 구독 관리 페이지로 이동합니다.
2. 자동결제 예정 정보를 확인합니다.
3. 결제 예정 플랜이 무엇인지 확인합니다.
4. Pro 자동결제 예정 항목이 따로 표시되는지 확인합니다.

### 기대 결과

- 자동결제 대상은 현재 유효한 최상위 플랜 기준으로 표시됩니다.
- 업그레이드 이전의 Pro는 잔여 기간 이월 상태로만 안내되어야 합니다.
- Pro와 Studio가 둘 다 다음 달 자동결제 예정으로 표시되면 실패입니다.

### 결과

## TC-USER-005. 업그레이드 후 Studio 기간이 끝나면 Pro 잔여 기간이 적용된다

### 목적

Pro에서 Studio로 업그레이드한 경우, Studio 기간 종료 후 Pro 잔여 기간이 다시 적용되는지 확인합니다.

### 사전 조건

- Pro에서 Studio로 업그레이드한 이력이 있습니다.
- 테스트 환경에서 날짜 변경 또는 관리자/개발용 시간 조정이 가능해야 합니다.

### 테스트 절차

1. 현재 플랜이 Studio인지 확인합니다.
2. 테스트 환경의 시간을 Studio 종료일 이후로 이동합니다.
3. 구독 상태 갱신 또는 스케줄러를 실행합니다.
4. 다시 로그인하거나 새로고침합니다.
5. 현재 플랜을 확인합니다.

### 기대 결과

- Studio 종료 후 Pro 잔여 기간이 남아 있다면 현재 플랜이 `Pro`로 표시됩니다.
- Pro 잔여 기간이 끝나기 전까지 Free로 떨어지면 실패입니다.
- Pro 잔여 기간 종료 후에는 Free 또는 다른 유효 플랜이 적용되어야 합니다.

### 결과

- [ ] 성공
- [ ] 실패

## TC-USER-006. Studio 사용자가 Pro로 다운그레이드를 예약한다

### 목적

Studio 사용자가 Pro로 변경할 때 즉시 Pro 결제가 되지 않고, Studio 종료 후 Pro로 변경 예약되는지 확인합니다.

### 사전 조건

- 현재 플랜이 Studio입니다.

### 테스트 절차

1. Studio 계정으로 로그인합니다.
2. 구독 관리 페이지에서 현재 플랜이 `Studio`인지 확인합니다.
3. `Pro로 변경` 또는 `Pro 선택` 버튼을 클릭합니다.
4. 안내 문구를 확인합니다.
5. 결제 화면으로 즉시 이동하는지 확인합니다.
6. 변경을 확정합니다.
7. 구독 관리 페이지에서 예약 상태를 확인합니다.

### 기대 결과

```text
Pro로 변경 예약됨
Studio는 현재 이용 기간 종료일까지 유지됩니다.
이후 Pro 플랜으로 변경됩니다.
```

- 즉시 Pro로 바뀌거나 즉시 결제되면 실패입니다.

4. 안내 문구를 확인합니다.
5. 변경을 확정합니다.

현재 이용 기간 종료일까지 Pro 플랜을 사용할 수 있습니다.
이후 Free 플랜으로 전환됩니다.

## 자동결제 스케줄러 수동 1회 실행 확인

FastAPI lifespan에서 스케줄러가 자동 실행되지만, 개발 중에는 아래 명령으로 1회 실행 결과를 확인할 수 있다.

```bash
cd backend
python -c "from services.subscription_scheduler import run_subscription_scheduler_once; print(run_subscription_scheduler_once())"
```

기대 결과:

```text
{'renewals': {'processed': ...}, 'scheduled_downgrades': {'processed': ...}}
```

테스트 모드별 동작:

- `TOSS_BILLING_TEST_MODE=true`: 실제 Toss API를 호출하지 않고 테스트 성공 응답으로 처리한다.
- `TOSS_BILLING_TEST_MODE=false` + `TOSS_SECRET_KEY=test_sk_...`: Toss 테스트 API를 호출한다. 테스트 키 환경에서는 결제 승인이 가상으로 이루어지며 실제 금액은 차감되지 않는다.
- `TOSS_SECRET_KEY=live_sk_...`: 실제 운영 결제로 이어질 수 있으므로 개발 테스트에서는 사용하지 않는다.

처리 대상 조건:

- 자동결제: `subscriptions.next_billing_at <= NOW()`인 유료 active 구독이어야 한다.
- 예약 다운그레이드: `subscription_plan_changes.effective_at <= NOW()`인 scheduled downgrade여야 한다.

# 15. 테스트 완료 기준

아래 조건을 만족하면 구독 사용자 흐름은 1차 완료로 볼 수 있습니다.

- 사용자가 직접 결제/변경/취소 흐름을 이해할 수 있습니다.
- 현재 플랜과 예약 상태가 화면에서 명확히 표시됩니다.
- 업그레이드는 즉시 결제 + 즉시 적용됩니다.
- 다운그레이드는 즉시 결제되지 않고 예약됩니다.
- Free 변경은 즉시 권한 제거가 아니라 구독 취소 예약으로 처리됩니다.
- 구독 취소 철회가 정상 동작합니다.
- 자동결제 성공/실패 결과가 사용자에게 표시됩니다.
- 새로고침/재로그인 후에도 구독 상태가 유지됩니다.
